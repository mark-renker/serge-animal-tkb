# v1 Reference Renders — Gauntlet Sound Bar (Phase 0)

Produced 2026-08-31, **offline from the legacy Faust sources** — the installed
v1 AU was not used (GAUNTLET.md sequencing constraint: these must exist before
the first v2 install replaces v1 at `aumu Satk Rnky`).

## How these were made

- DSP: `legacy/SergeAnimalTKB.dsp` (generated by `legacy/gen_dsp.py`, unmodified)
  compiled with Faust **2.85.9** (`/opt/homebrew/bin/faust -cn sergedsp
  -o serge_gen.cpp SergeAnimalTKB.dsp`).
- Driver: `legacy/render_gauntlet.cpp` (adapted from `legacy/render.cpp`, the
  same harness that made `legacy/demos/`). Build dir: `legacy/build/`
  (`clang++ -std=c++17 -O2 -I. ../render_gauntlet.cpp -o render_gauntlet`,
  then `./render_gauntlet <this dir>`).
- Format: **48 kHz, 16-bit PCM stereo** (both channels identical except
  `default_note60.wav`, which uses v1's pan law). Unlike `render.cpp`'s demo
  writer, gain is **fixed at 1.0** (no per-file peak normalization) so absolute
  levels are comparable across files.
- Every patch is an explicit parameter-event table in `render_gauntlet.cpp`
  (reproduced below in v1 terms). Verification analysis:
  `legacy/build/verify_renders.py` / `verify2.py`.

### Determinism

No live randomness anywhere in these renders. Faust's `no.noises` /
`no.pink_noise` use fixed compile-time LCG seeds reset by `init()`, so noise,
RVG, and S&H streams are bit-identical run to run (none are actually used by
these ten patches — TKB `random` mode is off, no noise source is routed).
Re-running the driver reproduces byte-identical WAVs.

### The v1 monitor-bus tap (applies to every file)

v1 has no direct module taps; the OUT page's **monitor bus** (`OUT/MIX/monitor
src`, one of the 31 matrix sources, + `monitor level`) is the only way to
audition a module output. Its path to the WAV is:

    src × monLvl × 0.7 × master(0.8) × midiGain(0.8) → fi.dcblocker → t3 softclip

i.e. gain **0.448 × monLvl**, then a DC blocker and a cubic soft clip
(`t3`). Consequences, documented rather than worked around:

- monitor level is set to **0.5** in most files (tap gain 0.224) to keep `t3`
  in its near-linear region (3rd-harmonic contribution ≈ −48 dB, and it is
  purely *harmonic*, so alias/non-harmonic measurements are unaffected).
- the DC blocker removes DC and sub-audio content — **the monitor bus cannot
  pass a slow envelope** (see file 7).
- unipolar sources (DUSG out 0..1) arrive AC-centered (±half swing).

Source-menu indices used below are v1's matrix source list:
1 = NTO sin, 2 = NTO saw, 3 = NTO var, 4 = DSG1 out, 6 = DSG2 out,
12 = VCFQ BP, 15 = VCM mid, 16 = VCM bot, 17 = RING, 26 = TKB gate,
28 = KEY gate.

## 1. `nto_saw_1975.wav` — NTO saw @ 1975 Hz (T03 reference)

5.00 s · peak 0.225 · RMS(L) 0.1278

**v1 settings** (all others default): `NTO keytrack = on`, `KEY freq = 1975 Hz`,
`monitor src = 2 (NTO saw)`, `monitor level = 0.5`. With keytrack on, f0 =
keyHz × 2^(coarse/12 + fine/1200) and coarse/fine stay 0, so the KEY freq
slider (0.01 Hz steps) sets f0 exactly. KEY glide = 0 gives a 0.1 ms smoothing
tau — settled within ~2 ms of sample 0.

**Achieved f0: 1975.000 Hz** (nominal; measured 1975.11 Hz by zero-crossing
count over 4.5 s, FFT peak bin 1974.89 Hz — both within measurement
resolution).

**Measured alias floor** (harmonics ±25 Hz excluded): worst non-harmonic
component **−27.0 dBc in 0–6 kHz** (at 4550 Hz) and **−22.4 dBc full-band**
(22325 Hz). v1's naive phase-accumulator saw is far outside T03's −60/−30 dBc
bands, as pre-registered.

**v2 equivalent**: cable NTO **SAW out → monitor** (OUT mixer monitor
selector); NTO tuned to 1975 Hz (1V/oct CV or knob), everything else idle.

## 2. `nto_shape_sweep.wav` — NTO var, shape stepped ×8 @ 220 Hz (T04 reference)

8.00 s · peak 0.231 · RMS(L) 0.1407

**v1 settings**: `NTO keytrack = on`, `KEY freq = 220 Hz`, `monitor src = 3
(NTO var)`, `monitor level = 0.5`; `NTO shape` stepped at t = 0..7 s to
k/7 for k = 0..7 (0.000, 0.143, …, 1.000). The shape ctl is smoothed
(`si.smoo`), so each step has a short (~ms) glide.

**Measured per-step spectral centroid** (Hz): 270, 406, 557, **622**, 557,
452, 383, 342. **Non-monotonic** — v1's crossfade morph (sine→tri→soft-square)
peaks in brightness at shape ≈ 0.43 and then *darkens*. This is the v1
out-of-band evidence for T04 (v2 requires monotonic centroid rise sine→'M').
f0 stayed exactly 220.0 Hz at every step.

**v2 equivalent**: NTO **VAR out → monitor**; WAVESHAPE knob (or shape-CV
input) stepped over 8 values min→max; pitch fixed at 220 Hz.

## 3. `vcm_mid_foldsweep.wav` — VCM middle fold sweep (T08 reference)

8.00 s · peak 0.244 · RMS(L) 0.1472

**v1 settings**: NTO sine 220 Hz (keytrack + KEY freq as above);
`PATCH/VCM/audio in A = 1 (NTO sin)`, `amt = 0.8`; `VCM bias = 0` (centered,
default); `monitor src = 15 (VCM mid)`, `monitor level = 0.5`; `VCM fold`
knob stepped at t = 0..7 s to k/7 (0 → 1 = knob max; internal drive
gm = 0.5·2^(4·fold) spans 0.5 → 8).

**Measured per-step centroid** (Hz): 308, 295, 303, 352, 532, 708, 1173, 1661
— rising from step 2 on, with a small dip at step 1 (v1's `sin()` folder is
nearly clean at low drive). At fold = 1.0 the waveform shows ~27 local extrema
over 4 cycles — v1's mid section does fold (multiple transfer turnarounds),
via an ideal `sin(π/2·(gm·x + bias))` with **no anti-aliasing** (v2's T08
alias band is where it lands out of band).

**v2 equivalent**: NTO **SIN out → VCM mid IN** (depth ~0.8 of nominal);
BIAS knob centered; FOLD knob stepped over 8 values 0→max; **VCM MID out →
monitor**.

## 4. `vcm_bot_full.wav` — VCM bottom @ full depth (T08 reference)

5.00 s · peak 0.226 · RMS(L) 0.1275

**v1 settings**: same input as file 3 (NTO sin 220 Hz → VCM audio in, amt
0.8, bias 0); `VCM fold = 1.0` (knob max) for the whole file; `monitor src =
16 (VCM bot)`, `monitor level = 0.5`.

**Measured harmonic structure** (re strongest, at n×220 Hz): H1 −9.8 dB,
H2 −113.6, H3 −6.8, H4 −108.5, H5 −3.6, H6 −111.6, H7 −2.3 (strongest),
H8 −113.6. **Purely odd-harmonic** — v1's bottom section is a symmetric
triangle-wrap, so even harmonics are absent. This is the key pre-registered
divergence: hardware (and T08) demand **even-harmonic dominance** (≥12 dB)
from the bottom section's cascaded full-wave rectifiers. v1 lands maximally
out of band here.

**v2 equivalent**: NTO **SIN out → VCM bottom IN** at full depth; **VCM BOT
out → monitor**.

## 5. `vcfq_ping.wav` — VCFQ ping, Q stepped ×4 (T07 reference)

8.00 s · peak 0.112 · RMS(L) 0.0057 (sparse pings — non-silent by design)

**v1 settings**: `TKB clock run = 1, rate = 2 Hz, gate len = 0.02 s` (TKB
gate as the 2 Hz pulse source); `PATCH/VCFQ/ping trig A = 26 (TKB gate), amt
= 1`; `VCFQ freq = 800 Hz`, `ping level = 0.9`; `PATCH/VCFQ/audio in A amt =
0` (removes the default VCM-mid feed so only pings ring); `monitor src = 12
(VCFQ BP)`, `monitor level = 0.9`; `VCFQ Q` stepped every 2 s: **2, 6, 15,
35** (4 pings per step).

**Measured decay** (ping peak → −40 dB): Q=2: 3.8 ms · Q=6: 11.1 ms ·
Q=15: 27.5 ms · Q=35: 63.3 ms — monotonically increasing with Q (the T07
law), with ping amplitude also growing (0.027 → 0.069). Note v1's "ping" is a
1-sample impulse into the SVF input, not the hardware's shaped pulse at the
BP integrator node.

**v2 equivalent**: any 2 Hz pulse (TKB GATE out or cycling DUSG END) →
**VCFQ TRIG (ping) in**; fc knob at 800 Hz; Q knob stepped low→high over 4
steps; **VCFQ BP out → monitor**.

## 6. `dusg_cycle.wav` — DUSG1 cycling at audio rate (T05c reference)

5.00 s · peak 0.109 · RMS(L) 0.0632

**v1 settings**: `DUSG1 cycle = on`, `rise = fall = 2.5 ms` (knob direct);
`PATCH/DUSG1/trig A amt = 0` (detach default KEY-gate trigger);
`PATCH/VCA1/audio in A amt = 0` (DSG1 out is VCA1's default CV — without this
the cycling envelope would open VCA1 and leak the default voice into the
mix); `monitor src = 4 (DSG1 out)`, `monitor level = 0.5`.

**Measured**: FFT fundamental at **200.00 Hz** (target ~200 Hz — v1 reaches
audio-rate cycling comfortably; requested ~200 Hz was reachable exactly).
Symmetric triangle, unipolar 0..1 at source, rendered AC-centered ±0.109 by
the output DC blocker.

**v2 equivalent**: DUSG1 in CYCLE mode, RISE/FALL at 2.5 ms; **DSG1 OUT →
monitor**.

## 7. `dusg_env_shape.wav` — DUSG1 slow transient, rise 0.5 s / fall 1.0 s (T05d reference)

6.50 s · peak 0.223 · RMS(L) 0.0763

**v1 LIMITATION (documented, not worked around silently)**: the monitor bus
runs through the output `fi.dcblocker`, so a 0.5 s/1.0 s envelope — sub-audio
content — cannot reach the WAV. The direct tap is kept as evidence:
**`dusg_env_shape_monitor_direct.wav`** (same triggers, `monitor src = 4`):
peak 0.0019, RMS 0.0011 — near-silent, only the envelope's derivative leaks
through. The shape is therefore rendered the only way v1 can express it:

**v1 settings**: `DUSG1 rise = 0.5 s`, `fall = 1.0 s`, cycle off, trig =
KEY gate (default routing); KEY gate pulsed at t = 0.3, 2.4, 4.5 s (0.2 s
high — DUSG completes its full transient regardless, and is
non-retriggerable during it); **DSG1 out → VCA2 CV** (`PATCH/VCA2/CV A = 4,
amt = 1`), VCA2 in linear mode (`vca2 exp = 0`) with `vca2 level = 0` so
gain == envelope exactly; VCA2 audio in = NTO sin at 1 kHz (keytrack + KEY
freq = 1000, `amt = 0.5`), `pan2 = 0.5`. The WAV's **amplitude envelope is
the DUSG output shape** riding a 1 kHz carrier.

**Measured**: rise 10→90% = 0.399 s (exactly 80% of the dialed 0.5 s —
linear), fall 90→10% = 0.797 s (80% of 1.0 s — linear). v1's slopes are pure
linear ramps with a hard corner at the target (no tanh soft landing) — the
T05d comparison point.

**v2 equivalent**: KEY GATE out → DUSG1 TRIG; RISE 0.5 s / FALL 1.0 s;
**DSG1 OUT → monitor** (v2's monitor must pass DC/slow CV — a capability v1
lacks) — or the same OUT → VCA CV audition patch.

## 8. `ring_sines.wav` — RING, NTO sin 300 Hz × DSG2 ~80 Hz (T09 reference)

5.00 s · peak 0.224 · RMS(L) 0.1261

**v1 settings**: NTO sin at 300 Hz (keytrack + KEY freq = 300) → `PATCH/RING/
X in A = 1, amt = 1`; DUSG2 `cycle = on, rise = fall = 6.25 ms` (~80 Hz
triangle, **unipolar 0..1**) → `PATCH/RING/Y in A = 6, amt = 1`; `ring gain =
1` (default); `monitor src = 17 (RING)`, `monitor level = 0.5`.

**Measured spectrum** (top peaks): 140, 220, **300**, 380, 460 Hz and 820,
900, 980 Hz — i.e. carrier 300 Hz **present, not suppressed**, with ±80/±160
Hz sidebands, plus the same cluster around the softclip's 3rd harmonic
(900 Hz). Two v1-isms on display: (a) the unipolar DSG2 modulator has a DC
component, so this is AM rather than balanced ring-mod; (b) v1's
`t3(x·y·2)` has zero carrier suppression machinery either way. T09's v2
target (≥55 dB carrier suppression at nominal trims with a bipolar
modulator, clean VCA behavior for DC carrier) is measured against this.

**v2 equivalent**: NTO **SIN out → RING X in**, DUSG2 (cycling ~80 Hz)
**OUT → RING Y in**, **RING out → monitor**.

## 9. `default_note60.wav` — untouched default patch, MIDI note 60 (T15 reference)

4.50 s · peak 0.407 · RMS(L) 0.0363, RMS(R) 0.0269 (stereo: pan1 = 0.35)

**v1 settings**: *no* parameter events — factory defaults only (default
routing: KEY gate → DUSG1 trig; NTO var → VCM in; VCM mid → VCFQ in; VCFQ LP
→ VCA1 in; DSG1 out → VCA1 CV). Note event exactly as `render.cpp` demos do
it: `KEY/freq = 261.63` + `KEY/gate = 1` at t = 0.25 s, `KEY/gate = 0` at
t = 2.25 s, then 2.25 s of tail.

**Measured envelope**: silence before the note (RMS 0.00000 for t < 0.25);
attack burst RMS 0.236 (0.25–0.30 s) decaying through 0.165 / 0.053 and fully
gone by t ≈ 0.55 s; release window and tail exactly 0.00000. **The default
patch is an AR pluck** (DUSG1 defaults: rise 1 ms, fall 250 ms — it fires
once per gate and does not sustain), so "2 s note + 2 s release" renders as a
~0.3 s pluck followed by true digital silence. That silence *is* the v1
contract (T15: removing the trigger cable → exact 0.0).

**v2 equivalent**: default cable set (same five cables as above), MIDI note
60 velocity ~100, held 2 s.
