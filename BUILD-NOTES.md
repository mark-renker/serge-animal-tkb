# SergeAnimalTKB — plugin build notes

How the AU/VST3 build works, every trap hit getting there, and how it was
verified. Run `./build.sh` to reproduce the whole thing.

## Status: built, installed, AU-validated

- `~/Library/Audio/Plug-Ins/Components/SergeAnimalTKB.component`
- `~/Library/Audio/Plug-Ins/VST3/SergeAnimalTKB.vst3`

Universal (x86_64 + arm64), `aumu` instrument, AU passes `auval -v aumu Satk Rnky`.
VST3 registers as Instrument|Synth. Codes: manufacturer `Rnky`, plugin `Satk`.

Rebuild with `./build.sh`. **`SergeAnimalTKB.dsp` is generated by `gen_dsp.py`** —
make UI/matrix changes there and regenerate, or they will be overwritten.

## What changed in the UI (vs. the original .dsp)

All of it is UI-label only — no DSP/audio logic was touched. These changes now
live in `gen_dsp.py`.

1. **Window size.** Everything now lives in one top-level tab group
   (`t:MAIN/` → VOICE / SLOPES / TIMBRE / TKB / OUT / PATCH). Laid out flat,
   the Faust JUCE UI stacks every group vertically (hslider = 350x50,
   vslider = 80x250), which is what produced the unusable window.
   **Measured: 1670 x 648** (was roughly 1500 x 2500).
2. **TKB steps** are now `[style:knob]` (100x100 instead of 80x250), so all
   4 rows x 16 steps are visible at once inside that window.
3. **PATCH matrix regrouped.** The original used `t:` groups containing raw
   controls, so the JUCE UI gave *every individual control its own tab* — one
   menu or one slider visible at a time, in a jumbled order. Now each
   destination is one row: `[A src][A amt][B src][B amt]`.
4. **Source selectors are dropdowns.** They were `nentry` + `[style:menu{...}]`,
   but `JuceGUI::addNumEntry` never checks `isMenu` (only `addSlider` does), so
   all 62 of them rendered as bare 0–30 number spinners. Changed to `hslider`
   (identical init/min/max/step) → real named ComboBoxes. Same treatment given
   to OUT's `monitor src`, which picks from the same 31 sources.

## Build gotchas hit (all encoded in build.sh)

- **`-jsynth` is required**, not just `-nvoices 1`. In `faust2juce`, `-nvoices`
  only sets `IS_SYNTH`; `JUCE_POLY` is defined solely by `-jsynth`. Without it
  the plugin is flagged as a synth but MIDI notes never drive freq/gate/gain.
- **Projucer must match the JUCE tree.** `~/dev/JUCE` is 8.0.14;
  `/Applications/Projucer.app` is 7.0.5 and `/Applications/JUCE/Projucer.app`
  is 8.0.2. Both make `JuceHeader.h` hard-error. Built a matching one at
  `~/dev/JUCE/extras/Projucer/Builds/MacOSX/build/Release/Projucer.app`
  (target is `"Projucer - App"`, not `Projucer`).
- **"Cycle inside a single target"** comes from JUCE's plugin copy step
  (`DEPLOYMENT_LOCATION=YES` + `DSTROOT=/`). Disable with
  `enablePluginBinaryCopyStep="0"` — it is a **per-`<CONFIGURATION>`** property,
  not per-exporter (putting it on `XCODE_MAC` silently does nothing).
- **Arch:** leave `osxArchitecture` unset. `"64BitUniversal"` is the legacy
  32/64-bit Intel setting and makes the build fail on deprecated i386.
- Two patches to Faust's generated code, both re-applied by `build.sh`:
  JUCE 8 `getStringWidth` (6 sites), and guarding the `fFirstCall` block with
  `#ifndef JUCE_POLY` (it references `fDSP`, which doesn't exist in poly mode).

## The dropdown off-by-one was a real bug (patch C)

Not a rendering artifact. `uiMenu` in Faust's JUCE architecture computes
`defaultitem` two different ways:

- **constructor:** `defaultitem = fComboBox.getNumItems()` → 1-based, so the
  following `setSelectedItemIndex(defaultitem - 1)` is correct;
- **`reflectZone()`:** `defaultitem = int(i)` → already 0-based, then subtracts
  1 *again*.

So once `reflectZone` ran, value 28 selected item 27 ("KEY pitch") and value 0
selected index −1 (blank). And because `setSelectedItemIndex` defaults to
`sendNotificationAsync`, it fired `comboBoxChanged`, which writes
`fValues[getSelectedId()-1]` **back into the DSP zone** — so the patch-matrix
defaults were being actively corrupted, not merely mis-drawn.

Fix (patch C in `build.sh`): drop the extra `- 1` and pass
`juce::dontSendNotification`, since reflecting the zone into the UI must never
write back.

Verified after the fix — all defaults read correctly via the accessibility API:

    DUSG1  KEY gate, OFF, OFF, ...      (trig A = 28)
    VCFQ   VCM mid,  OFF, ...           (audio in A = 15)
    VCM    NTO var,  OFF, ...           (audio in A = 3)
    VCA1   VCFQ LP,  OFF, DSG1 out, OFF (audio in A = 11, CV A = 4)

i.e. the intended voice: NTO var → VCM mid → VCFQ LP → VCA1, gated by KEY gate.

## End-to-end verification of the installed AU

`au_render_test.c` (in this folder) instantiates the *installed* component,
sends MIDI note 60 and measures the output. Note 60 = C4 is deliberate: at C4
the KEY pitch CV is exactly 0, so if the trigger source were wrongly "KEY pitch"
the envelope could never fire and the result would be silence.

    ./au_render_test                          rms=0.070595 peak=0.365772  AUDIBLE, clean
    ./au_render_test --set 257786756 0.0      rms=0.000000                silent   (trig src -> OFF)
    ./au_render_test --set 257786756 0.93333  rms=0.070595 peak=0.365772  AUDIBLE, clean
    ./au_render_test --list                   dumps all 229 parameters

Disconnecting the trigger gives *exactly* zero output and restoring it returns
the identical signal — so host automation reaches the DSP and the patch matrix
behaves as designed. (`--set` prints a stale read-back from
`AudioUnitGetParameter`; that is a quirk of the little test harness, the render
clearly reflects the new value.)

## Also worth knowing

- `.jucer` has `buildStandalone="1"` so the standalone app can be built for
  visual checks. It is **not** installed — only AU + VST3 are.
- The JUCE standalone persists parameters to
  `~/Library/Application Support/Serge Animal TKB.settings` (note the *spaces* —
  searching for "SergeAnimal" misses it). Delete it before any defaults test,
  or you will be looking at stale state from a previous build.
